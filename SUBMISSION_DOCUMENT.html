2. Technical Architecture Summary

The application is architected as an end-to-end real-time communication platform utilizing Socket.IO over an HTTP/Express backend paired with a high-performance React + Vite + TypeScript client:

  • Security & Authentication: REST login verifies credentials and issues a signed JSON Web Token (JWT). The WebSocket handshake uses an io.use() authentication guard that validates the JWT before establishing the persistent connection.
  • User-to-Socket Mapping: Active users are registered in an internal bidirectional map (userSocketsMap and socketUserMap), enabling multi-tab synchronization and clean lifecycle cleanup on disconnection.
  • Room Segregation: Conversations use isolated Socket.IO channels created with deterministic room IDs (roomIdFor(u1, u2)). Clients join rooms via socket.join(), ensuring private message exchange without data leakage.
  • Persistent Messaging: Message histories are stored with structured schemas maintaining sender ID, sender name, receiver ID, payload body, and ISO-8601 timestamps.

3. Real-Time Pipeline Documentation

1. Handshake Auth:
   Client (auth: { token }) ──> io.use(authenticateToken) ──> socketUserMap.set(socket.id, user)
   
2. Room Management:
   Client (contactId) ───────> socket.on('room:join') ───────> socket.join(roomId)

3. Message Dispatch:
   Client (message:send) ───> Server persists to storage ────> io.to(roomId).emit('message:new')

4. Real-Time Feedback:
   Client (typing: true) ────> socket.to(roomId).emit('user:typing') ──> Live Animated Indicator

5. Presence Lifecycle:
   socket.on('disconnect') ──> Clean userSocketsMap ─────────> io.emit('presence:update', { online: false })

4. Persistent Database Schema (SQL Definition)

CREATE TABLE messages (
    id UUID PRIMARY KEY,
    room_id VARCHAR(128) NOT NULL,
    sender_id VARCHAR(64) NOT NULL REFERENCES users(id),
    sender_name VARCHAR(255) NOT NULL,
    receiver_id VARCHAR(64) NOT NULL REFERENCES users(id),
    body TEXT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_messages_room_created ON messages (room_id, created_at ASC);
